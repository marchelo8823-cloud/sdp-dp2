# Дайджест замечаний операторов (16.11.2026) → наш пульт SDP-DP2

Источник: `reference/incoming_1118/Операторы_пульт_2026-11-16.md` — разбор
пульта предыдущего ядра (sdpcore C++) четырьмя профилями: K-Pos (старший
DPO), Praxis/Mega-Guard, MT, новичок. Ниже — что переносим в наш
Python/QML-пульт, и что уже закрыто.

## Уже закрыто в нашем пульте (до этого дайджеста)

- Шапка состояния при отказах: «СЧИСЛЕНИЕ КУРСА», «УПОР СНЯТ — НЕТ КУРСА»,
  «СЧИСЛЕНИЕ ПОЛОЖЕНИЯ» — красная/жёлтая плашка вместо зелёного «всё хорошо»
  (замечания всех профилей №1/9/12/13).
- Блок «ЧТО ДЕЛАТЬ» под шапкой в деградации (новичок №4).
- Обратный отсчёт до снятия упора при потере курса (`release_in` в баннере;
  у всех профилей №5/14/21).
- «Вероятный уход» при счислении положения растёт со временем
  (`excursion_m`, обновляется каждый такт) — против «0,00 м» и разового
  «≈0,1 м» (все профилей №3/7/15/16).
- Кнопка «Вернуть упор» — явное действие оператора после снятия
  (K-Pos №14, MT №17: ничего не включать без оператора).
- Watch circles предупреждения/аварии на плане + аварии по выходу
  (Praxis №6, MT №9). Ложная авария на старте подавлена (arm после входа
  в жёлтый круг).
- Тренды 5 мин: ошибка позиции, ветер, суммарная тяга (K-Pos №11).
- Время по часам в аварийном журнале (`clock` в записи) — K-Pos №20.

## Сделано в этой итерации (отбраковка и опорные системы)

- Ядро `sdp/redundancy.py` v2: тесты «замирание / разброс / скачок /
  расхождение с медианой» по первым разностям (движение судна не даёт
  ложных срабатываний); веса 1/σ² в вотировании; состояния
  `ok / rejected / deselected / failed`.
- Две системы в работе и разошлись → авария «расхождение систем
  положения» БЕЗ автоотбраковки — какую снимать, решает оператор
  (как GYRO_DISAGREE; нельзя отбраковать здоровую по глючной).
- Гирокомпасы: те же тесты + расхождение пары > 2°.
- Инъекции инструктора: `fail` (нет данных), `frozen`, `noisy`, `drift`
  («плывущая» система — сценарий многолучёвости у платформы, MT ⚠).
- Аварии на каждый датчик: отказ / отбраковка с причиной / возврат
  (Praxis №5, K-Pos №8).
- Панель «Опорные системы» в QML: состояние, причина, вес %, σ,
  «● принят» у гиро, кнопки «Снять / Вернуть» (MT №3/№5, Praxis №7).
- Пульт инструктора: кнопки сбоев «PRS1 завис / PRS2 шум / PRS3 плывёт /
  ГИРО2 шум», возврат всех датчиков одной кнопкой.

## Сделано (джойстик, 19.11)

- Режимы **MAN JOY** (чистое ручное: продольная/боковая сила + момент,
  без ветровой компенсации) и **AUTO JOY** (ручные силы + автокурс) —
  замечание всех профилей, высокий приоритет.
- Джойстик действует и после аварийного снятия упора (HDG_LOST) — это
  его главное назначение; интегратор PID в ручных режимах не копится.
- Панель «Джойстик» в QML: круговая площадка (вверх = вперёд, вправо =
  на правый борт), вертикальный ползунок момента, кнопка «Центр»,
  переключатели режимов; шапка показывает MAN JOY / AUTO JOY оранжевым.

## Очередь дальше (по приоритету операторов)

1. Диаграмма возможностей на экране (поляра предельного ветра + текущий
   ветер) — K-Pos №10, MT №6; `capability.py` уже считает — вывести.
2. Подтверждение (второе нажатие / Apply) для «Точка = здесь», сдвига

3. Метки каждой PRS на плане (увидеть расхождение до отбраковки) — MT №4.
4. Пояснение «что делать» к каждой аварии в журнале (кнопка «i») —
   K-Pos №5.
5. Режим регулятора и усиление на экране (Controller Mode / Gain) — K-Pos №12.
6. Состояние анализа последствий «считается / приостановлен / устарел» —
   MT №10; класс из данных судна — K-Pos №23.
7. Имитаторные элементы скрывать вне режима ИМИТАЦИЯ (MT №1, новичок №1).

## Не переносим / отклонено

- Возврат упора после HDG_LOST только через Standby (K-Pos 8.1.7) —
  у нас уже есть «Вернуть упор» как явное действие оператора, эквивалент
  по смыслу; автоматический возврат не делаем.
- Командная строка ядра на рабочем экране — в нашем пульте её нет вовсе
  (только кнопки), вопрос закрыт архитектурой.
