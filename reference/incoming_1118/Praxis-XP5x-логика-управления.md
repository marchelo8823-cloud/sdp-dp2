# Praxis СДП-2: логика блока движителя (XP51–XP58) и блока XP49

Источник: исходники PAL1131 из выгрузки `Praxis_для_СДП-2_Praxis_20261111.json`, версия кода 1.026 (2018-06-08), цикл задачи 100 мс. Только чтение, в конфигурации ничего не менялось.

⚠ Это разбор текста программ. На работающей системе не проверялось. Программа серверов СДП (в коде названа `DP.pro`) в выгрузку не входит.

## 1. Кто решает, какой сервер управляет

Блок движителя **не выбирает** между серверами. Он исполняет то, что пришло в теги `THRUSTER_OUT[n].CHW_RPM.*` и `CHW_ANGLE.*`, от кого бы оно ни пришло. Выбор активного сервера делается на стороне серверов (`MODE_SYNC`, программа `DP.pro`).

В XP49 прямо записано: «VLAN; ONLY 1 DP_SERVER IS SENDING LIFE_CHECKS / IN CONTROL», то есть до блоков доходят данные только одного, активного сервера.

Регистры состояния серверов в блоке только распаковываются и выводятся на дискретные выходы «в управлении» и «в резерве» (индикация). Обрабатываются три: DP1, DP2 и JC (джойстик). Канал третьего сервера СДП есть, но в коде не используется.

## 2. Регистр состояния сервера (`MODE_SYNC.STATUS_OUT[n]`, DWORD)

| Бит | Значение |
|---|---|
| 0 | меняющийся бит «жизни» (маскируется, маска 2097150) |
| 1 | AVAILABLE, сервер доступен |
| 2 | STANDBY, в резерве |
| 3 | FAIL, отказ |
| 4 | CTRL_REQ, запрос управления |
| 5 | CTRL_RELEASE, отдача управления |
| 6 | CTRL, в управлении |
| 7 | SIM, режим имитации |
| 8 | JSM, джойстик ручной |
| 9 | JSA, джойстик авто |
| 10 | APOS, автопозиция |
| 11 | APILOT, автопилот |
| 12–20 | распаковываются, но в блоке не используются |

Правила:
- Регистр должен **меняться не реже чем раз в 5 с** (за счёт бита 0). Иначе блок считает сервер отказавшим: обнуляет регистр и ставит FAIL.
- Регистр принимается, только если его значение не меньше 2 (то есть установлен хотя бы бит AVAILABLE).
- «В управлении» гасится, если установлен SIM.

## 3. Счётчик управления по движителю (`CHW_RPM.CTRL_LC`, `CHW_ANGLE.CTRL_LC`)

Одно число несёт и «жизнь», и команду:

- `значение = N × 100 + данные`;
- `N` (сотни и выше) должно быть больше нуля, иначе число игнорируется;
- `данные = 1` означает «взять управление», любое другое значение означает «снять»;
- число должно **меняться не реже чем раз в 10 с**. Иначе команда управления снимается.

Команда управления также снимается при отказе платы ввода-вывода. Тестовый режим (`TEST_ACTIVE`) включает команду управления принудительно.

Шаг/обороты и угол имеют отдельные счётчики, поэтому управление ими берётся раздельно.

## 4. Последовательность взятия управления

1. Сервер пишет `CTRL_LC` с данными 1 и обновляет его.
2. Блок выставляет дискретный выход «запрос управления» на движитель (`OUTPUT_CTRL`, `OUTPUT_RPM_CTRL`, `OUTPUT_ANGLE_CTRL`).
3. Движитель отвечает дискретным входом «в управлении» (`INPUT_CTRL` или `INPUT_RPM_CTRL`). Это и есть признак `RPM.CTRL` / `ANGLE.CTRL` для сервера.
4. После прихода подтверждения уставка шага держится нулевой в течение `PAR_RPM_OUT_CTRL_DELAY` секунд.
5. Если задан `PAR_RPM_OUT_CTRL_TO`, запрос управления по шагу снимается через это время после подтверждения (импульсный запрос).

## 5. Уставки

- Значение **999** означает «не менять»: блок оставляет прежнюю уставку.
- При потере управления уставка шага и угла **сразу становится 0**, без плавного спада.
- Темп: за цикл 100 мс уставка шага меняется не более чем на `PAR_RPM_RAMP / 10`. То есть параметр задан в %/с; 0 отключает ограничение.
- Знак упора (`THRUST SETPOINT`) задаёт дискретные выходы «вперёд» / «назад».
- Выход шага: `(уставка + OFFSET) × 100 / SCALE`, ограничение 0…100 % (ток 4–20 мА).
- Выход угла: ограничение ±180°, затем `угол × 100 / SCALE + 50`. При SCALE = 360 включён гистерезис 10° на переходе через ±180°.
- К выходам добавляется «шум» 0,01, меняющийся раз в 500 мс.

## 6. Обратная связь

- Шаг: `вход × SCALE / 100 − OFFSET`, ограничение ±100 %. При входе ниже −12,5 % (обрыв токовой петли) значение обнуляется и ставится отказ.
- Угол: `(вход − 50) × SCALE / 100`, то есть ±SCALE/2 (360 → ±180°, 90 → ±45°), сглаживание по 5 отсчётам, затем смещение. Поддерживается вход sin/cos.
- Счётчик жизни блока (`LIFE_CHECK`): +500 каждые 500 мс, сброс на 10 000; при отказе платы равен 0.

## 7. Тревоги блока

| Признак | Условие |
|---|---|
| Расхождение (`DIFF_HIGH`, бит 4 регистра тревог) | разность уставки и факта больше `DIFF_LIMIT` дольше `DIFF_DELAY`. Проверка включается через 10 с после того, как есть и команда управления, и подтверждение |
| Обрыв контура обратной связи (бит 1) | отказ входа дольше 2 с |
| Обрыв контура уставки (бит 2) | отказ выхода (дискретный вход или контрольный ток ниже 2 мА) дольше 2 с |

Общая тревога держится импульсом 10 с.

## 8. XP49 (общий блок)

- Тот же счётчик жизни и распаковка регистров DP1, DP2, JC.
- Выходы «отказ СДП» включаются, только если отказали **оба** сервера DP1 и DP2.
- Выходы «СДП в управлении» включаются, если в управлении DP1 или DP2.

## 9. Что это значит для нашего подключения

Чтобы управлять движителем через существующие блоки, наш сервер должен:
1. вести регистр состояния по таблице из раздела 2 и менять его чаще чем раз в 5 с;
2. вести счётчик `CTRL_LC` по разделу 3 для шага и для угла каждого движителя;
3. дождаться подтверждения «в управлении» и выждать задержку перед ненулевой уставкой;
4. писать уставки в процентах (±100) и градусах (±180), использовать 999 как «не менять»;
5. следить за счётчиком жизни блока и регистром тревог.

Нерешённые вопросы:
- ⚠ Блок не разбирает, чей сервер пишет. Два одновременно пишущих сервера будут перебивать друг друга. Разделение сделано сетью (VLAN) и логикой серверов, которой в выгрузке нет.
- ⚠ Протокол доставки тегов OPC (вариант, адреса, права) в выгрузке не описан.
- ⚠ Биты 12–20 регистра состояния не расшифрованы.
