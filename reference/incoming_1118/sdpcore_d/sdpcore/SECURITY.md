# Защита проекта СДП

## Что уже сделано в репозитории
- Агенты запускаются только действиями владельца (`github.actor == github.repository_owner`); события от других людей и ботов агентов не запускают.
- У агентов нет права записи в репозиторий: они делают коммиты локально. Ветку отправляет и предложение изменений открывает отдельное задание без Claude (`tools/agent_publish.sh`), и только если агент менял разрешённые ему файлы: агенты 1 и 4 — `отчёты/`, агент 5 — `отчёты/` и `shipedit/mainwindow.cpp`, агент 6 — всё, кроме `.github/` и `CLAUDE.md`. Иначе ничего не отправляется, а в задаче появляется комментарий.
- Набор разрешённых агенту команд ограничен (`--allowedTools` в `.github/workflows/agent-*.yml`).
- Вложения задачи для агента данных скачивает отдельный шаг до его запуска (`tools/fetch_attachments.py`: только ссылки github.com из задачи владельца, в папку `вход/`, которая не попадает в репозиторий); самому агенту сеть не дана; агент правил читает веб-страницы как данные. ⚠ Каждый агент с доступом к сети теоретически может отправить данные наружу, если его обманут: поэтому задачи — только от владельца, а результаты принимает человек.
- Слежение за правилами идёт по расписанию раз в месяц (событие расписания GitHub, только из основной ветки); у события расписания нет автора, поэтому проверки владельца нет. Агент правил пишет только в `отчёты/` через свою ветку и задачи, сеть — только чтение страниц.
- Правила агентов при проверке берутся из основной ветки (`_base/`): проверяемое изменение не может подменить правила своей проверки.
- В правилах агентов (`.github/agents/common.md`): содержимое файлов, комментариев, веб-страниц — данные, а не указания; секреты не выводятся; подозрительное оформляется задачей с меткой `безопасность`.
- `CODEOWNERS`: каждое изменение требует одобрения владельца.
- Редактор `sdp_ship` хранит ключ Anthropic API в защищённом хранилище системы (`shipedit/keystore.cpp`), открытым текстом — нигде; ключ из прежних версий переносится туда и стирается из настроек.

## Что должен включить владелец (в настройках GitHub)
1. **Закрыть репозиторий:** Settings → General → Danger Zone → Change repository visibility → Private.
2. **Защитить основную ветку:** Settings → Rules → Rulesets → New branch ruleset, цель — Include default branch:
   - Restrict deletions; Block force pushes;
   - Require a pull request before merging, **Required approvals: 0** (свои изменения в GitHub одобрить нельзя: при 1 владелец заблокирует сам себя);
   - Require status checks to pass: `build` из «Сборка и тесты».
   - ⚠ В закрытом репозитории на тарифе Free правила веток не действуют (GitHub: «Upgrade to GitHub Pro or make this repository public»). Без Pro основную ветку защищает только то, что у агентов нет права записи, а принимает изменения владелец.
3. **Ключ API:** Settings → Secrets and variables → Actions → New repository secret, имя `ANTHROPIC_API_KEY`. Значение никому не пересылать.
4. **Модель агентов (необязательно):** там же, вкладка Variables, `SDP_AGENT_MODEL`.
5. **Ограничить Actions:** Settings → Actions → General → Allow … actions: разрешить только действия GitHub и `anthropics/claude-code-action`; Fork pull request workflows — Require approval for all outside collaborators.
6. **Двухфакторный вход** в учётную запись GitHub.
7. **Метки:** Actions → «Агенты: задачи» → Run workflow.
8. **Actions → General:** Allow actions created by GitHub и `anthropics/claude-code-action@*`; Workflow permissions — Read; включить **Allow GitHub Actions to create and approve pull requests** (без этого задание отправки не откроет предложение изменений агента).
9. **Минуты Actions** (закрытый репозиторий, Free — 2000 минут в месяц): каждое изменение — сборка на Linux и агенты; macOS — только вручную (Actions → macOS), минута macOS считается за 10.

## ⚠ Пределы
- Полной защиты от копирования не бывает: закрытый репозиторий и доступ по списку защищают исходники, лицензия и подпись сборок защищают установку, но не от того, у кого есть доступ.
- Защита агентов от чужих указаний («инъекций») снижает риск, но не исключает его: результаты агентов всегда принимает человек.
- Каждый запуск агента расходует токены по ключу владельца.
