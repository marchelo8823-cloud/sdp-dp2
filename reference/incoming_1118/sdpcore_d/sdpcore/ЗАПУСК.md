# Ядро СДП — запуск

## Сборка
```
cd ~/Downloads
unzip -o sdpcore_2026-11-16c.zip
cd sdpcore
cmake -S . -B build
cmake --build build -j
cd build && ctest
```
Должно пройти 32 теста (с пультом, `-DSDP_BUILD_HMI=ON`, — 36; вместе с шестью сценариями имитатора, проверкой возврата в точку по 10 погодам (несколько минут), двумя проверками на Python 3 — отчёт по записям и скачивание вложений — и проверкой отправки изменений агентов). Нужны CMake 3.16+ и компилятор C++17, внешних библиотек нет.

## Редактор данных судна (нужен Qt 6)
На Mac один раз: `brew install qt`. Затем из папки `sdpcore`:
```
cmake -S . -B build -DSDP_BUILD_EDITOR=ON -DCMAKE_PREFIX_PATH=$(brew --prefix qt)
cmake --build build -j
./build/shipedit/sdp_ship data/чертёж/Данные_судна_с_чертежом.xlsx
```
- Вкладки «Вид сверху / сбоку / спереди»: загрузить картинку, привязать двумя точками, обвести фигуры вручную или «Контур по картинке», затем «Перенести в корпус».
- «Распознать (Claude)» — нужен интернет и ключ Anthropic API (вводится в «Распознавание Claude…»; хранится в «Связке ключей» macOS или «Диспетчере учётных данных» Windows, открытым текстом не сохраняется).
- «Проверить ядром» — та же проверка, что `ship load`.
- «Сохранить» — книга `.xlsx`, которую потом загружает ядро. Картинки держите рядом с книгой.

## Пульт оператора (нужен Qt 6)
На Mac `brew install qt` (тот же, что для редактора). Из папки `sdpcore`:
```
cmake -S . -B build -DSDP_BUILD_HMI=ON -DCMAKE_PREFIX_PATH=$(brew --prefix qt)
cmake --build build -j
./build/hmi/sdp_hmi
```
1. «Открыть судно…» → книга судна, например `data/Данные_судна_пример.xlsx`.
2. «Запустить имитатор…» → `tests/scenarios/имитатор_быстро.xlsx` (ускорение ×20) или `data/Данные_имитатора_пример.xlsx` (реальное время).
3. «Взять все движители» → «Позиция». Кнопки «Ожидание», «Курс», «Позиция» и «Снять все» срабатывают со второго нажатия: после первого кнопка мигает «Ещё раз: …», второе нажатие — в течение 3 с. Точку и курс двигают кнопки «Сдвиг точки» и «Курс».
   При потере положения появляется жёлтая кнопка «Держать здесь (не возвращаться в точку)».
4. Внизу — командная строка ядра (те же команды, что в `sdp_run`, например `sim wind 15 90`, `sim thr off AZ1`, `sim off GNSS1`).

Сразу с судном и имитатором:
```
./build/hmi/sdp_hmi --ship data/Данные_судна_пример.xlsx --sim tests/scenarios/имитатор_быстро.xlsx --cmd "thr_take all" --cmd position
```

## Запуск ядра
Из папки `build`:
```
./sdp_run
```
Ядро запускается без данных и пишет: «Состояние: НЕТ СУДНА».

## Работа с имитатором
Команды с клавиатуры, по очереди:
```
ship load ../data/Данные_судна_пример.xlsx
sim start ../data/Данные_имитатора_пример.xlsx
thr_take all
position
status
move 10 0
hdg 45
sim wind 15 90
sim thr off BOW1
class 2
ca
sim off GNSS1
sim off GNSS2
sim off LASER
here
sim reset
standby
sim stop
quit
```
После `ship load` ядро пишет «ЖДУ ДАТЧИКИ», после `sim start` через несколько секунд — «ГОТОВ».

| Команда | Что делает |
|---|---|
| `class 2` или `class 3` | включить анализ последствий отказа (по умолчанию выключен); `class off` — выключить |
| `ca` | запас по каждой группе наихудшего отказа сейчас |
| `ca 25 90` | то же при введённой погоде: ветер 25 м/с с 90° от носа (третье число — течение, м/с) |
| `here` | после потери положения держать судно там, где оно окажется, а не возвращать в заданную точку |

## Работа с датчиками судна
1. В книге судна на листе «Датчики» заполните «Подключение» (udp, tcp или serial) и порт или устройство.
2. Если есть контроллер движителей, заполните лист «Выдача».
3. `./sdp_run`, затем `ship load Данные_судна.xlsx`. Когда пойдут курс и положение — «ГОТОВ».

## Проверка своей книги
```
./sdp_run --check ../data/Данные_судна.xlsx
```
- «ОШИБКА» — судно не загрузится, исправьте названную ячейку;
- «По умолчанию» — пустая необязательная ячейка и что принято вместо неё;
- «Оценка» — расчёты по введённым данным для самопроверки.

## Что изменилось 16.11.2026
- Потеря курса: через 2 с без гирокомпасов — HDG_DR, ещё через 2 с — HDG_LOST и нулевой упор (как K-Pos).
- Движитель без обратной связи через 2 с — тревога THR_FB_LOST и вывод из распределения упоров.
- После потери положения — команда `here` («держать здесь»); по умолчанию — плавный возврат в заданную точку. Возврат после повторной потери больше не раскачивает судно.
- Анализ последствий отказа: `class 2|3`, `ca`; тревога CA_DRIFT_OFF. Группы — колонка «Группа отказа» листа «Движители» (в примере ГРЩ-1, ГРЩ-2).
- Пульт: подтверждение смены режима повторным нажатием, кнопка «Держать здесь».
- Редактор больше не теряет встречный упор при сохранении.
- Возврат в точку после потери положения: без перерегулирования (до 1 м), скорость до 0,25 м/с, оценка неизвестной силы после возврата измерений сходится быстрее.

## Что изменилось в 1.3
- В редакторе виды сами рисуют схему по числам, введённым в «Корпус» (зелёный пунктир). В расчёт «По чертежу» схема не входит; «Сделать фигурами» превращает её в фигуры для правки.

## Что изменилось в 1.2
- Новая программа `sdp_ship`: данные судна в таблицах и чертёж из простых фигур в трёх видах; площади, центр парусности, осадка и размеры считаются по фигурам.
- Подложка-фото с привязкой двумя точками, подсказка контура по картинке и распознавание через Claude.
- Ядро не менялось; книга, сохранённая редактором, загружается ядром так же, как заполненная вручную.

## Что изменилось в 1.1
- Ядро запускается без данных и само ждёт их: НЕТ СУДНА → ЖДУ ДАТЧИКИ → ГОТОВ → УДЕРЖАНИЕ.
- Судно загружается командой `ship load`; загруженное судно — основа модели. Сменить судно можно только в ожидании.
- Имитатор запускается отдельно: `sim start <книга имитатора>`, своя книга `Данные_имитатора`.
- Из книги судна убран лист «Работа» (источник данных и параметры имитатора).
- Журнал включается параметром `--log файл.csv`.

## Проверка всего проекта одной командой
Из папки `sdpcore` (не из `build`). С редактором (нужен Qt 6):
```
tools/ci_build.sh
```
Без редактора:
```
tools/ci_build.sh --no-editor
```
Итог — в `test-out/итог.txt`, сценарии удержания и отказов — в `test-out/сценарий_*.txt`.

## Агенты в GitHub
1. Установить приложение Claude для GitHub на репозиторий SDP-Core-cpp.
2. Внести секрет `ANTHROPIC_API_KEY` (Settings → Secrets and variables → Actions).
3. Actions → «Агенты: задачи» → Run workflow (создаст метки).
4. Задача агенту: открыть задачу (issue) и поставить метку: `агент:координатор`, `агент:тестировщик`, `агент:администратор`, `агент:данные`, `агент:правила`, `агент:отображение` или `агент:операторы`. Агент правил раз в месяц сам проверяет новые редакции.
5. Свои предложения изменений агенты проверяют сами; изменение от агента — поставить метку `агент:проверка`.
Подробно — `SECURITY.md` и `.github/agents/README.md`.
