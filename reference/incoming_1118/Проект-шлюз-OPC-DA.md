# Проект: чтение данных СДП Praxis через классический OPC (DA)

Статус: проект на согласование. Кода нет. Основан на выгрузке конфигурации СДП-2 и таблице соответствия тегов.

## 1. Цель и границы

Получать в наше ядро данные работающей СДП Praxis **только на чтение**: датчики, системы положения, обратную связь движителей, электростанцию, а также собственные расчёты Praxis для сравнения.

Не входит: любая запись в систему Praxis, управление движителями, изменения конфигурации Praxis.

## 2. Схема

```
Сервер СДП Praxis ──OPC DA──► ШЛЮЗ (Windows) ──UDP, одна сторона──► наше ядро + HMI (Mac/Linux/Windows)
   (не меняется)              отдельный ноутбук                     режимы «наблюдение» и «тень»
```

Три части:
1. **Шлюз** на Windows: читает теги у сервера OPC и пересылает их по сети.
2. **Приёмник в ядре**: превращает посылки шлюза в те же входные данные, что дают датчики.
3. **Проигрыватель записей**: подаёт в ядро файл, записанный шлюзом, чтобы всё проверялось без судна.

## 3. Шлюз

- Программа под Windows на .NET (у вас уже используется .NET 8).
- Читает список тегов из текстового файла, который делается из нашей таблицы соответствия. Менять список можно без пересборки.
- Подписывается на изменения значений у сервера OPC; сам сервер не опрашивает чаще, чем тот отдаёт.
- **Записи в OPC в программе нет совсем**: нет ни одного вызова записи. Это проверяется просмотром кода.
- Пишет всё принятое в файл-журнал (время, тег, значение, качество). Журнал потом проигрывается.
- Показывает на экране: связь с сервером, число тегов, сколько из них «плохого качества», возраст последних данных.

Библиотеку доступа к OPC DA выберу при реализации. ⚠ Какая из них работает с .NET 8, я не проверял; возможно, шлюз придётся собирать под .NET Framework 4.8. На работу это не влияет.

## 4. Обмен «шлюз → ядро»

- UDP, только в одну сторону. Ядро шлюзу ничего не отправляет.
- Текстовые строки в формате NMEA с контрольной суммой: ядро уже умеет их разбирать и проверять.

```
$PXOPC,<номер посылки>,<время шлюза>,<тег>,<значение>,<качество>*hh
```

- Быстрые величины (датчики, движители): при изменении, но не реже 1 раза в секунду.
- Медленные (электростанция, расчёты Praxis): раз в секунду.
- Раз в секунду служебная строка «шлюз жив, связь с сервером есть/нет».

Оценка нагрузки: ~270 тегов входа и ~800 для сравнения, это единицы килобайт в секунду.

## 5. Приёмник в ядре

Новый модуль рядом с существующим приёмом NMEA. В настройках судна новый раздел, где каждому каналу ядра сопоставлен тег и пересчёт:

| Канал ядра | Тег Praxis | Пересчёт |
|---|---|---|
| курс GYRO1…3 | `GYRO_OUT[n].HEADING` | градусы → радианы |
| ветер WIND1…3 | `WIND_OUT[n].WIND_REL.T / .A` | узлы → м/с, градусы → радианы |
| качка MRU1…3 | `MRU_OUT[n].ROLL / .PITCH` | градусы → радианы |
| положение GPS1…3 | `GPS_OUT[n].RAW.LAT / .LON` | в местные координаты |
| лазеры, трос | `LASER_OUT[n].FIX.N / .E`, `TAUTWIRE_OUT[1].FIX.N / .E` | метры |
| обратная связь THR1…8 | `THRUSTER_OUT[n].RPM.FB`, `.ANGLE.FB` | см. п. 8 |
| располагаемая мощность | `PMS_INTERFACE.BUS_TOTAL[n].AVAILABLE` | сумма по шинам |

Правила достоверности:
- признак отказа датчика от Praxis (`…FAIL`) или плохое качество OPC → измерение в ядро не подаётся;
- данные старше 2 с → канал считается потерянным;
- шлюз молчит 3 с → тревога «нет связи со шлюзом», все каналы потеряны.

Значения для сравнения (силы, уставки, режим Praxis) складываются отдельно и во входы ядра не попадают.

## 6. Режимы работы

1. **Наблюдение.** HMI показывает данные Praxis: датчики, движители, электростанцию, течение. Ядро ничем не управляет.
2. **Тень.** Ядро дополнительно считает свои команды по тем же данным, в том же режиме и для той же заданной точки, что у Praxis. HMI и журнал показывают расхождения: наши команды движителям против команд Praxis, наша оценка возмущения против оценки Praxis.

В обоих режимах выдача команд наружу выключена и не включается настройкой.

## 7. Главный риск: доступ к серверу OPC

Классический OPC работает через механизм Windows (DCOM). Чтобы читать сервер **с другого компьютера**, на сервере должны быть разрешены удалённые подключения и заведена учётная запись. Варианты:

| Вариант | Что нужно | Изменения на сервере СДП |
|---|---|---|
| А. Удалённый доступ уже настроен (например, для операторских станций) | имя сервера OPC и учётная запись | нет |
| Б. Удалённый доступ не настроен | настроить DCOM на сервере | **да**, это правка системы с классом |
| В. Шлюз ставится на сам сервер СДП | установить программу на сервер | **да** |
| Г. Шлюз ставится на существующую операторскую станцию, у которой доступ уже есть | установить программу на станцию | на сервере нет, на станции да |

⚠ Какой вариант возможен, из выгрузки не видно. Это нужно выяснить на судне до начала работ. Варианты Б и В я бы без согласования с владельцем системы и классом не делал.

## 8. Открытые вопросы

1. **Имя сервера OPC** (ProgID) и компьютер, на котором он работает.
2. **Удалённый доступ**: настроен ли он, с каких компьютеров сейчас читаются теги.
3. **Кодировка широты и долготы** в `GPS_OUT[n].RAW` (диапазон ±2 000 000) не расшифрована. Решится по первой записи.
4. **Обратная связь движителя**: Praxis даёт шаг или обороты в %, ядро ждёт упор. Либо берём готовый упор в кН (`THRUSTER_OUT[n].T`), либо нужна зависимость упора от шага.
5. **Вертикальной качки** среди тегов нет; наш оценщик волнения без неё работать не будет.
6. **Частота обновления** тегов на сервере неизвестна.

## 9. Этапы

| № | Что делается | Где | Результат |
|---|---|---|---|
| 1 | Приёмник в ядре, проигрыватель, раздел настроек; проверка на искусственной записи | у меня | тесты, HMI показывает «данные Praxis» из файла |
| 2 | Шлюз: чтение, журнал, пересылка | у меня, проверка на вашем Windows | программа и инструкция |
| 3 | Первая запись на судне (у причала), 10–30 минут | вы | файл журнала |
| 4 | Разбор записи: единицы, знаки, кодировки; правка таблицы пересчётов | у меня | подтверждённая таблица |
| 5 | Режим «тень» и отчёт о расхождениях | у меня, затем судно | сравнение с Praxis |

Этап 1 не зависит от судна, его можно начинать сразу. Этап 2 я не смогу проверить на настоящем сервере OPC: проверю на учебном сервере, окончательная проверка на судне.

## 10. Что меняется в проекте

- Ядро: новый модуль приёма, раздел настроек, две тревоги (нет связи со шлюзом, данные устарели), тесты.
- HMI: признак источника данных «Praxis», страница сравнения для режима «тень» (на этапе 5).
- Новая отдельная программа-шлюз (в ядро не входит).
- Существующие режимы, имитатор и файлы настроек не меняются.
